# 예하와 정현 — 로그인 없는 공유 웹페이지

## 사용 순서 (10분 정도의 초기 설정)

1. https://supabase.com 에서 **무료 프로젝트**를 만듭니다.
2. 프로젝트의 **SQL Editor → New query** 에서 `database.sql` 전체를 붙여넣고 **Run**.
3. **Project Settings → Data API** 의 Project URL과 **API Keys**의 **publishable key(또는 legacy anon key)**를 복사해 `config.js`의 두 값을 바꿉니다. **secret / service_role 키는 절대로 입력하지 마세요.**
4. GitHub에서 공개 저장소를 만들고 `index.html`, `config.js`를 최상위에 업로드합니다. **비밀 링크가 적힌 `PRIVATE_LINKS.txt`는 절대 GitHub에 올리지 마세요.** (`database.sql`은 업로드할 필요 없습니다.)
5. **Settings → Pages → Deploy from a branch → main / (root) → Save**. 배포 URL을 확인합니다.
6. 별도로 제공한 `PRIVATE_LINKS.txt`의 `#key=...` 값을 배포 URL 뒤에 붙여 예하/정현에게 각각 전달합니다. 예: `https://yourname.github.io/our100/#key=...`
7. 각자 자신의 URL로 한 번 접속하면 그 휴대폰에 접속 정보가 저장됩니다. 이후에는 보통 주소로 다시 접속할 수 있습니다.

## 사용법
- 내 답변을 작성하고 **저장하고 다음**을 눌러야 서버에 제출됩니다.
- 반대편 답변은 두 사람 모두 해당 질문을 제출하면 함께 공개됩니다.
- 서로 다른 답변은 **생각이 조금 달라요** 버튼으로 표시할 수 있습니다.
- 열린 페이지는 약 7초마다 새 답변을 확인하고, 휴대폰 화면으로 다시 돌아왔을 때도 새로고침합니다.
- 상대방이 아직 답하지 않은 문항에서는 상대방의 답변 내용이 서버에서도 공개되지 않도록 처리합니다.

## 보안·주의
- **로그인이 없으므로 전용 URL 자체가 비밀번호입니다.** 링크를 가진 제3자는 그 사람의 답변을 읽고 수정할 수 있습니다. 카카오톡 등으로 개인에게만 전달하세요.
- `PRIVATE_LINKS.txt`에는 원본 비밀 코드가 있습니다. 공개 GitHub 저장소에 업로드하지 마세요.
- `database.sql`에는 원본 코드가 아닌 해시만 들어갑니다. Supabase에서 비밀 코드를 다시 조회할 수 없으므로, 개인 링크 파일을 안전하게 보관하세요.
- publishable key는 공개되어도 되는 프로젝트용 키이지만 DB 테이블에 anon 권한을 개방하면 안 됩니다. SQL 파일은 두 테이블에 직접 접근하지 못하도록 구성했습니다.
- 비밀번호 없이 완전한 신원 확인은 불가능하며, 공개 함수 남용/대량 요청에 대한 별도 방어는 없습니다. 소규모 개인 사용 목적으로 권장합니다.
- 별도 서버 프로세스 운영은 필요 없지만, 답변이 공유되려면 Supabase 데이터베이스 연결이 필요합니다.
